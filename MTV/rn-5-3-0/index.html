Chapter 1. Migration Toolkit for Virtualization 5.0

The release notes describe technical changes, new features and enhancements, known issues, and fixed issues.

1.1. MTV new features and enhancements

Migration Toolkit for Virtualization (MTV) 5.0 introduces the following features and enhancements.

Selecting predefined secrets for LUKS encryption supported during plan creation

Previously, you had to manually enter LUKS encryption keys in the UI when creating a migration plan. With this update, MTV supports selecting a predefined secret containing LUKS encryption keys during plan creation. As a result, you can select an existing secret instead of manually entering encryption keys for each plan.

MTV-2834

Configuring node selectors for importer pods supported for warm migrations

Previously, configuring node selectors for importer pods, also known as virt-v2v Convertor pods, was supported for cold migrations only. With this update, MTV supports configuring node selectors for importer pods during warm migrations from VMware virtual machines (VMs). As a result, you can schedule destination nodes for virt-v2v Convertor pods during warm migrations.

MTV-3208

Dedicated migration hosts for VMware vSphere migrations (Technology Preview)

Previously, MTV extracted migration data directly from the ESXi host where the source virtual machine (VM) was registered. With this update, you can designate specific ESXi hosts as dedicated migration hosts in the StorageMap custom resource (CR). You specify these hosts in the vsphereXcopyPluginConfig section of the storage map. As a result, data extraction tasks run on isolated hosts, protecting production workloads from migration load. This capability is a Technology Preview feature.

MTV-3264

Support for Nutanix as a source provider (Technology Preview)

With this release, MTV enables you to define Nutanix as a source provider by using the web console or command-line interface (CLI). You can define Nutanix as a source provider by using the UI or the command-line interface (CLI). This capability is a Technology Preview feature.

MTV-4465

Microsoft Hyper-V migrations are fully supported

With this release, migrations from Microsoft Hyper-V are fully supported. Previously, this feature was available as a Technology Preview. You can migrate VMs from Microsoft Hyper-V hosts and Windows Server Failover Clusters to OpenShift Virtualization.

MTV-4461

Configuring storage access modes supported in the web console

Previously, you had to manually edit YAML files to configure storage access modes. With this update, MTV enables you to select storage access modes directly on the Storage maps page in the web console. You can select ReadWriteOnce, ReadWriteMany, or ReadOnlyMany modes for each storage mapping. In addition, the console displays a warning if you select ReadWriteOnce for a storage type capable of ReadWriteMany.

MTV-5496

Option to resume warm migrations after conversion failure (Technology Preview)

If a migration fails during disk conversion after a successful disk copy, you can resume the migration without recopying disks. This feature applies to migrations where disk copy and conversion are separate phases (for example, warm migrations or cold migrations with storage offload). If the source virtual machine (VM) was powered on after the failed migration, the copied disks may be inconsistent. Start a new migration instead. This capability is a Technology Preview feature.

MTV-6993

Excluding specific disks from migration plan

Previously, you could exclude only shared disks attached to a virtual machine (VM) in a migration. With this update, you can exclude any disk attached to a VM in the Plan settings section of a migration plan and the plan wizard.

MTV-6426

Offline migrations in ROKS no longer fail due to certificate errors

Previously, offline virtual machine (VM) migrations failed in Red Hat OpenShift on IBM Cloud (ROKS) environments. This occurred because MTV configured invalid certificates on intermediate DataVolume resources. As a consequence, users encountered certificate errors that blocked the migrations. With this update, MTV probes the export proxy Transport Layer Security (TLS) endpoint before setting the certificate configuration map. It omits the certificate if the VMExport certificate authority (CA) does not verify but system trust does. As a result, offline migrations in ROKS environments complete successfully despite the unverified certificates.

MTV-6458

Overlay mechanism for virt-v2v-in-place migrations (Developer Preview)

Previously, virt-v2v-in-place conversion wrote changes directly to the disk. Consequently, conversion failures left the base disk in a corrupted, non-bootable state with no option for rollback. With this release, MTV creates a QEMU Copy-On-Write version 2 (QCOW2) overlay for each disk, leaving the disk read-only. As a result, virt-v2v-in-place conversions write changes onto the overlay and merge the overlay to the disk if the conversion succeeds. The overlay is deleted if the conversion fails, leaving the base disk in its original state. This capability is a Developer Preview feature.

MTV-5332

Support for immediate and planned cutover options for warm migrations

Previously, you had to pick a past date as a workaround to start immediate cutover for warm migrations. With this release, the Plan cutover menu includes Cutover as soon as possible (default) and Cutover at a specific time options in the web console. As a result, you do not need to select a past date for an immediate cutover.

MTV-5513

Post-migration status tracking for Windows virtual machines

Previously, MTV showed the Completed status even though the Windows virtual machine is performing post-migration tasks. With this update, you can check the post-migration status for Windows VMs when they reboot multiple times to install drivers, guest agents, remove VMware tools, or configure networking.

MTV-5506

Checking supported guest operating system for virtual machines

Previously, you had to manually check whether the guest operating system (OS) was supported while selecting a virtual machine in a plan. With this update, you can view the supported guest OS for selected VMs in a plan, on the Plan details page, and on the Provider details page. You can also filter the VMs by the supported guest OS before you create a migration plan.

MTV-5502

Excluding specific disks from migration plan

Before this update, you could exclude only shared disks attached to a virtual machine (VM) in a migration. With this update, you can exclude any disk attached to a VM in the Plan settings section of a migration plan and the plan wizard.

link: MTV-6426

Two-phase virtual hard disk transfer for Hyper-V VM transfers (Developer Preview)

With this release, MTV performs a two-phase transfer of Virtual Hard Disk (VHD) and Virtual Hard Disk v2 (VHDX) for Hyper-V virtual machines (VMs). When you set preCopySourceDisks:type to true, MTV copies the VHDX files from the Server Message Block (SMB) share and the virt-v2v tool then performs in-place guest operating system customization. This capability is a Developer Preview feature.

MTV-6718

Data streaming from source to target clusters in VMware migrations (Developer Preview)

Before this update, cold and warm migrations from VMware vSphere used source platform APIs. With this update, you can reduce source platform API dependency for migrations through a stateless virtual machine (VM) deployed in the source cluster for data transfer. The stateless VM performs direct data streaming to the connected OpenShift cluster. This capability is a Developer Preview feature.

MTV-6582

Migrating Windows and Linux virtual machines from IPv6 VMware environments

Before this update, migrating Windows and Linux virtual machines (VMs) with IPv6 configurations resulted in errors. With this update, you can migrate Windows VMs with static IPv6 addresses and routing configurations, connect to vCenter servers and ESXi hosts with IPv6-only or dual-stack configurations, and run MTV on IPv6-only Red Hat OpenShift clusters.

MTV-2897

Centralized provider alerts on the Provider details page

Provider alerts are centralized on the Provider details page. As a result, you can view all relevant provider warnings in one place rather than in the Conditions section.

MTV-6656

Storage copy offload migrations report XCOPY usage per disk

With this update, MTV propagates the xcopyUsed indicator from the populator pod to the migration plan status. Previously, this information was only available as a transient Prometheus metric that was lost when the populator pod completed. Each disk transfer task includes an xcopyUsed annotation that shows whether the storage array used hardware-accelerated copy or a software fallback. As a result, you can identify which disks benefited from XCOPY and troubleshoot performance differences across storage configurations.

MTV-5871

Monitoring runtime migration issues supported on MTV web console

Before this update, you had to manually track plan-related alerts in a specific plan. With this release, MTV displays automated alerts for migration failures, stalled migrations, persistent volume claim provisioning issues, and insufficient resources in the target namespace. To make monitoring large-scale migration easier, you can track migration issues on the Overview page or on the Plan details page.

link: MTV-5498

IP address settings for vNICs of Windows VMs in the NetworkMap

With this release, you can configure the network IP mode for virtual network interface cards (vNICs) of Windows virtual machines (VMs) in the NetworkMap. As a result, you can specify whether vNICs preserve the static IP address from the source network, use a Dynamic Host Configuration Protocol (DHCP)-assigned IP address, or are excluded from the static IP configuration after migration.

MTV-5268

Deep inspection is fully supported

With this release, deep inspection is fully supported. Before this update, this feature was available as a Technology Preview. You can use deep inspection to analyze virtual machine (VM) disk images before migration and find compatibility issues that standard inspection might miss. As a result, you can plan remediation before starting the migration.

MTV-4473

Automated removal of VMware components in migrated virtual machines

Before this update, Windows virtual machines (VMs) had VMware drivers and tools after migration. As a result, service stack failures and compatibility issues with KVM or virtio affected the migrated OpenShift VMs. With this release, the VMware components are automatically removed in the post-migration workflow after you configure feature_vsphere_vmware_driver_removal:true in the ForkliftController custom resource (CR).

1.3. MTV known issues

Migration Toolkit for Virtualization (MTV) 5.0 has the following known issues.

Windows Server 2019 VM enters a reboot loop after migration with VMware driver removal enabled

After you migrate a Windows Server 2019 virtual machine (VM) from vSphere with feature_vsphere_vmware_driver_removal:true in the ForkliftController custom resource (CR), the VM reboots in an indefinite loop. As a consequence, you are unable to log in to the VM even after the VMware driver is removed without any errors.

No known workaround exists.

MTV-6506

VMware driver left in Windows VMs after migration

After you migrate a Windows virtual machine (VM) from VMware to Red Hat OpenShift with feature_vsphere_vmware_driver_removal:true in the ForkliftController custom resource (CR), the VMware driver remains in the VM. Consequently, the VM can be affected by unnecessary service failures and error logs.

No known workaround exists.
